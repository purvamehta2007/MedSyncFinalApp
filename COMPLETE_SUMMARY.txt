HOW IT WORKS NOW
================================================================================

1. USER OPENS APP
   http://localhost:5173 (React/Vite)

2. USER UPLOADS MEDICINE IMAGE
   Click "Upload" or "Take Photo"

3. FRONTEND SENDS TO BACKEND
   POST http://localhost:8000/scan
   with image file

4a. IF BACKEND RUNNING:
   - FastAPI receives image
   - EasyOCR extracts text
   - Returns candidates: ["Paracetamol", "Acetaminophen"]
   - Frontend searches drug database
   - Shows drug information

4b. IF BACKEND NOT RUNNING:
   - Request times out (10 seconds)
   - Frontend shows helpful message
   - Suggests: "Backend not running, please start it"
   - Offers fallback: Manual search input
   - User can type medicine name instead

5. RESULT
   - Drug information displayed
   - Or fallback to manual search
   - No crashes, no silent failures

TECHNICAL DETAILS
================================================================================

Backend Stack:
  - FastAPI (Python web framework)
  - Uvicorn (ASGI server)
  - EasyOCR (Optical Character Recognition)
  - PyTorch (Deep learning for OCR)
  - OpenCV (Image processing)

API Endpoints:
  GET  http://localhost:8000/      - Health check
  POST http://localhost:8000/scan  - Process image

Request Format:
  multipart/form-data with "file" field

Response Format:
  {
    "medicine": "Paracetamol",
    "candidates": ["Paracetamol", "Acetaminophen", "500mg"]
  }

Performance:
  - First scan: 5-10 seconds (model loading)
  - Subsequent: 1-2 seconds per image
  - Memory: ~2GB for PyTorch
  - Works on CPU or GPU

CORS:
  - Allows localhost:5173
  - Allows 127.0.0.1:5173
  - Add more origins as needed

================================================================================
KNOWN LIMITATIONS & WORKAROUNDS
================================================================================

PyTorch Installation:
  - Can be slow/fail on some systems
  - Workaround: Use Docker (handles it)
  - Or use pre-built wheels from pytorch.org

Large Model Download:
  - EasyOCR downloads ~500MB on first run
  - Requires internet connection
  - Takes 5-10 minutes first time
  - Cached after that

GPU Support:
  - Works on CPU but slower
  - GPU support available with CUDA
  - See docs for GPU setup

Memory Usage:
  - ~2GB for models
  - System needs at least 4GB RAM
  - Works fine on modern machines

Vercel Deployment:
  - Vercel timeouts after 30 seconds
  - PyTorch models take 5-10 seconds to load
  - First request might timeout
  - Solution: Run backend separately
